# Navigation

**Principle:** on the web there is no sense of scale, direction or location. Navigation has to supply all three. Dropped on any page, a user should know where they are and where they can go.

## The trunk test

Open a deep page directly, as if arriving from a search result. Without scrolling far or clicking, find each of these. Each one you cannot find quickly is a failure.

| ID | Check | How to check |
|---|---|---|
| N1 | Site identity | Logo or site name, top-left, on every page |
| N2 | Page name | Every page has one. It is prominent, it frames the content, and it matches the words of the link that led here |
| N3 | Main sections | The primary navigation is visible, or one obvious tap away on a phone |
| N4 | Local navigation | The options at the current level are shown |
| N5 | "You are here" | The current section is highlighted in the navigation, clearly enough to notice |
| N6 | Search | A search box or search icon, unless the site is very small |

## The rest

| ID | Check | How to check |
|---|---|---|
| N7 | The logo links home | Click it from a deep page |
| N8 | Navigation is in the same place and looks the same on every page | Compare three pages. Exceptions: focused flows such as checkout may strip it down |
| N9 | Section names are plain | "Pricing", "Docs", "Blog". Not "The Hub", "Launchpad" |
| N10 | Utilities are present and quieter than sections | Sign in, Help, Account, Cart: easy to find, visually secondary |
| N11 | Breadcrumbs on deep sites | At the top, with the last item being the current page and not a link |
| N12 | Lower levels are designed too | Navigation at level 3 and 4 is as clear as at level 1. Check a deep page, not only the top |
| N13 | Back works | The browser or system back button returns to the previous view with its state intact |
| N14 | Search results are usable | A search for a common term returns relevant results and says what was searched |

For apps: N1 to N5 map to the screen title, tab bar or drawer, the selected tab, and the back control.
